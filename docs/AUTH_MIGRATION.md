# Перенос входа с Base44 на Supabase Auth + закрытие личных данных

Слой 2 из [BASE44_REMOVAL.md](BASE44_REMOVAL.md). Делается первым, потому что от него зависят
приватность данных, переписка, избранное, уведомления и дилерская панель.

## Почему это срочно

1. **Личные email открыты всем.** Правила доступа отдают гостям целые строки публичных таблиц,
   вместе с email авторов и продавцов: `created_by` (все открытые таблицы), `seller_id`
   (8 таблиц объявлений), `owner_email` (дилеры), `author_email` (отзывы, статьи).
   Сейчас это 26 объявлений с email аккаунтов.
2. **Вошедшие пользователи для новой базы — гости.** Вход идёт через Base44, Supabase о нём
   не знает, поэтому запись не проходит: сообщения, избранное, история просмотров,
   уведомления (проверено: база отклоняет такую запись, код 42501).
3. Закрыть email раньше переноса входа нельзя: дилерская панель и «Мои объявления»
   находят «свои» записи как раз по этим полям.

## Что уже готово в базе

- `profiles.id` = `auth.users.id`, `legacy_id` хранит старый id Base44.
- Правила доступа построены на `auth.uid()` и `auth_email()`; владелец объявления
  определяется по `created_by_id` / `seller_id` / дилеру.
- Импорт уже проставляет `created_by_id` по email, как только появятся профили.

## Как войдут существующие пользователи

Пароли из Base44 не выгружаются. Учётные записи создаются заранее по email, без пароля.
При первом входе человек нажимает «Забыли пароль?» и задаёт новый, или входит через Google
с тем же email. Объявления, избранное и переписка остаются привязаны к нему.

## Чего не делаю без владельца

- Не создаю учётные записи и не храню ключи: service-role ключ, ключи Google и Resend
  вводятся только в настройках Supabase/Vercel, не в чат.

- **Site URL:** `https://carunity.eu`
- **Redirect URLs:**
  - `https://carunity.eu/**`
  - `https://www.carunity.eu/**`
